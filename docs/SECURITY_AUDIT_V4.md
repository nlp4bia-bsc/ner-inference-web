# V4 authentication and isolation audit

## Initial audit — before implementation

Baseline: b8d4d4f on branch work. Executed the full existing regression with
`BROWSER_TESTS=1 work/locked-env/bin/python -m pytest -q`: **128 passed in 83.68s**.
Inspected composition, all HTTP routers/methods, upload middleware, job service,
SQLite admission/state machine/migrations, document repository, scientific pipeline,
exports, browser clients and the README/security/deployment/retention documentation.

Blocking findings:

- Possession of a token grants anonymous access to status, texts, incremental
  results, annotations, statistics, viewer and exports; jobs have no owner.
- Home exposes the NER form; language/model catalog and API docs/OpenAPI are public.
- No user accounts, password hashing, server sessions, CSRF, email verification,
  recovery, account suspension, administrative separation or per-user quotas.
- Name/email in request metadata are not authenticated identities. A matching
  historical email must never claim or transfer an old job.
- Existing 72-hour retention/expiry, private filesystem, original-offset validation,
  CSP/textContent rendering, bounded ingestion, durable FIFO and worker isolation
  are useful controls to preserve; they do not replace authentication/authorization.

Required changes: default-deny backend gate; mandatory live server sessions;
object ownership without an administrator bypass; additive versioned account/
session/token/audit/owner migrations; Argon2id; CSRF; authentication throttling;
verified-email admission; atomic account-derived quotas; audited administration
with MFA; explicit email delivery configuration; real browser and adversarial tests.

Existing endpoint inventory is captured by the versioned router source; the final
method/route/authentication/ownership/coverage matrix and independent review
findings will be recorded after implementation, with executed results and limits.

## Delivered controls and final review

V4 adds a default-deny ASGI gate before admission, live server sessions, strict
central/service owner checks, Argon2id, CSRF for every write, verified-email
processing, account-derived quotas, durable encrypted mail, TOTP/recovery codes,
audited account administration and English/Spanish/Catalan auth flows. Admin has
no clinical data bypass. The complete75 method/route pairs and coverage are in
[ROUTE_SECURITY_V4.md](ROUTE_SECURITY_V4.md), generated by
`python -m scripts.inventory_routes`. New aliases cannot bypass the central job
prefix guard. Unsupported WebSocket connections are closed; slash redirects cannot
silently downgrade the public HTTPS origin behind a proxy.

An independent reviewer inspected the implementation and reproduced concrete
attacks/flows using temporary SQLite, actual registration/email/login and a
controlled scientific predictor. [SECURITY_REVIEW_V4.md](SECURITY_REVIEW_V4.md)
records nine findings, their corrections and rechecks: bootstrap elevation of an
existing email; reset hashing before token validation; session resurrection after
logout-all; stale-actor writes after delayed bodies; missing recovery-code display;
malformed non-ASCII crypto input; TOTP future-step replay; CLI password exceptions;
and HTTPS/SMTP secret handling. Every blocking authentication/ownership failure
found was corrected rather than accepted.

Integration additionally caught and fixed:

- Chromium forms under no-referrer use Origin:null. The strict exception requires
  same-origin Fetch Metadata AND the valid CSRF proof. Null with missing/none/
  same-site/cross-site metadata fails403. The reviewer assessed this policy; actual
  browser root/prefix flows and positive/negative API tests execute it.
- Vanilla HTML formatting altered Jinja attribute conditions. The four affected
  templates are explicitly excluded from that formatter and all templates compile
  in regression tests; actual browser flows exercise their rendered forms.
- Session guards initially threatened the one-time MFA recovery-code result after
  enrollment revoked the cookie. That result now intentionally omits the guard,
  displays codes once, and clears them on leaving. A real browser admin flow saves
  the codes, reauthenticates and performs account changes.
- A terminal viewer must clear on revocation and on a different user's login in
  another tab. The guard compares the server profile with the rendered user ID,
  rechecks on focus/pageshow/visibility and timer, and uses credential-free
  same-origin cross-tab notifications. Tokens/clinical data are never persisted.
- Heartbeat/progress polling no longer renews idle time. Real interaction uses a
  CSRF-protected activity POST; absolute expiry remains fixed during rotation.

## Static and dependency audits

Bandit runs over app/scripts at medium/high severity. The reviewed suppressions
are narrow and documented inline: fixed/allowlisted SQL identifiers with bound
values, a benchmark's trusted pinned-git source, and an already validated local
fast tokenizer with local_files_only. No unsuppressed medium/high findings remain
at the recorded final scan. This is not a claim that static analysis proves safety.

`pip-audit --no-deps --disable-pip -r requirements.lock` audits the fully pinned
HTTP runtime. The initially selected cryptography48.0.1 had published advisories;
it was upgraded to50.0.2 and the repeated HTTP audit has zero known findings.
Versioned reports are in security/. CPU/GPU registry-package audits were also run
from their locks (CPU local-version suffix normalized for registry lookup).
The direct pinned ner_lab source archive is not a PyPI advisory-database entry.

Both neural profiles still report these upstream torch2.10.0 advisories:

| Advisory | Reported affected component | Available resolution |
|---|---|---|
| PYSEC-2026-139 | Local pt2 loading/deserialization | No fixed version reported by the audit database |
| PYSEC-2025-194 | Local torch.jit.script memory corruption | Audit database lists2.13.0 |

The pinned ner_lab revision declares **torch==2.10.0** in its own optional dependency
([upstream source](https://github.com/nlp4bia-bsc/ner_lab/blob/8640d4797b081a5f6b66d9b45c11269542a79a26/pyproject.toml)).
Silently overriding that exact dependency would abandon the audited scientific
runtime. HTTP clients cannot upload/load checkpoints or invoke JIT/pt2 interfaces;
only immutable administrator-provisioned, offline-validated local checkpoints are
accepted. These restrictions reduce the attack surface but do not erase package
advisories. **Resolve these upstream risks before declaring a neural production
profile hardened.** The default Docker/CI HTTP image does not install Torch.

GitHub Actions gates the auth/security regression, browser flows, Ruff, Bandit and
HTTP dependency audit. CPU/GPU profile findings are disclosed separately rather
than hidden by an advisory ignore flag or a claim of universal zero findings.

## Residual risks and deployment conditions

Real SMTP-provider round trips, BSC TLS/HSTS/trusted-proxy integration, clinical
checkpoints/GPU/full neural images and external-user load/penetration tests remain
outside this local execution. Supply the institution's legal notices/data policy,
private encrypted volumes/backups, key/MFA recovery procedure, correct forwarded-IP
trust and operational limits. TOTP is phishable; host compromise/session theft and
already delivered downloads cannot be undone by the UI. SQLite remains single-host.
No formal certification or invulnerability claim is made. Exact final regression,
clean-environment, package and container results are recorded in VERIFICATION.md.
